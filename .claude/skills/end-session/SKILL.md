# Завершення сесії

Наступна сесія почнеться з чистого контексту. Усе, що не потрапило в документи,
буде втрачено — це єдина причина, чому цей skill існує.

Виконай по порядку.

## 1. Подивитися, що змінилося

Переглянь зміни в робочій папці й коротко скажи вголос, що було зроблено цієї сесії.

## 2. Оновити `docs/CURRENT_STATE.md`

- що зроблено цього разу;
- який наступний крок (конкретно, не «продовжити роботу»);
- що змінилося у відкритих питаннях: які закрилися, які з'явилися;
- оновити дату.

## 3. Перевірити, чи були нові рішення

Якщо під час сесії прийнято рішення, яке впливатиме на майбутню роботу, додай його
в `docs/DECISIONS.md` у форматі:

**Рішення** → **Чому** → **Ціна** (чим за це платимо).

Номер — наступний по порядку. Скасовані рішення не видаляй, познач як Superseded
й додай посилання на те, що прийшло замість них.

## 4. Запитати про коміт

Покажи, що саме зміниться, і запропонуй повідомлення коміту.

**Не комітити без відповіді.** Історія комітів публічна й є частиною портфоліо (D13),
тому рішення про те, що і як туди потрапляє, приймає автор.

## 5. Сказати, з чого почати наступного разу

Одне речення. Щоб наступна сесія починалася з роботи, а не зі згадування.
