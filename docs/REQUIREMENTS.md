# REQUIREMENTS — MVP

> Результат Phase 0 (product definition). Функціональні та нефункціональні вимоги.
> Обґрунтування рішень — у `DECISIONS.md`.

## Scope

### Must have

| # | Вимога |
|---|--------|
| R1 | Завантаження книги у форматах EPUB, FB2, HTML, TXT, PDF |
| R2 | Перетворення книги на єдине внутрішнє представлення (розділи, абзаци, речення) |
| R3 | Reader UI, придатний для тривалого читання з телефона |
| R4 | Виділення будь-якого слова або фрази в тексті |
| R5 | Переклад речення мовою допомоги з підсвіченою відповідністю виділеному (див. нижче) |
| R6 | Збереження позиції читання |
| R7 | Вибір рівня англійської (A1–C2) |
| R8 | Автоматичне виділення об'єктивно складних місць |

R8 реалізується після R1–R6 і не блокує їх.

### Не входить у MVP

Бібліотека з кількох книг, словник збережених слів, модель знань користувача,
авторизація, аудіо, вимова, квізи, гейміфікація, переписування тексту під рівень
(Mode B), повний переклад книги, соціальні функції, рекомендації.

## R5 — головна взаємодія, детально

**Вхід у AI-запит:** виділена фраза, речення цілком, невеликий контекст навколо,
мова допомоги, рівень користувача.

**Очікуваний структурований вихід:**

- переклад речення мовою допомоги (за замовчуванням українською, D25);
- фрагмент (або фрагменти) цього перекладу, що відповідають виділеній фразі;
- тип конструкції та приблизний CEFR-рівень, якщо це фраза, а не окреме слово.

**Краєві випадки, які треба обробити:**

1. **Модель повернула фрагмент, якого немає в перекладі** (переформулювала його).
   Дія: показати переклад без підсвітки. Не показувати помилку, не ламати екран.
2. **Відповідність розривна.** Українською відповідник англійської фрази може
   розпастися на кілька несуміжних частин речення. Формат відповіді має допускати
   список фрагментів, а не один.
3. **Виділення перетинає межу речення.** Брати речення, у якому починається виділення.
4. **Речення дуже довге.** Обмежити обсяг контексту, що йде в запит.
5. **Немає мережі або помилка API.** Показати зрозумілий стан і кнопку «спробувати ще».

**Кешування:** результат для пари (фраза, речення) кешується. Повторний клік по тому
самому місцю не має коштувати нового запиту.

## R8 — автоматичне виділення, детально

Виділяються об'єктивно складні елементи: рідкісна лексика, phrasal verbs, ідіоми,
сталі словосполучення, важкі граматичні конструкції.

Рівень користувача зсуває поріг, але не є фільтром «усе вище рівня».

**Обмеження щільності:** якщо кандидатів на екрані забагато, показувати лише
найскладніші. Виділеного має лишатися мало на будь-якому рівні.

**Доступність:** тип виділеного НЕ можна кодувати лише кольором. Потрібна друга
ознака — форма підкреслення, товщина або накреслення (WCAG 1.4.1).

## Нефункціональні вимоги

| Область | Вимога |
|---|---|
| Платформа | Mobile-first web. Desktop працює, але телефон — головний сценарій |
| Продуктивність | Відповідь на клік — цільово 1–2 секунди. Показувати стан очікування |
| Пам'ять | Телефон не має тримати весь файл книги в пам'яті. Парсинг — на сервері |
| Безпека | Ключі API — тільки на сервері, через env. Ніколи не в клієнті й не в репозиторії |
| Доступність | Керування розміром шрифту, контрастом, темна тема. Виділення — не лише кольором |
| Приватність | Завантажені книги користувача не публікуються й не використовуються повторно |

## Стани, які треба спроєктувати

Ці стани користувач бачить реально, і про них найчастіше забувають:

- порожній стан: книги ще немає;
- завантаження й розбір файлу;
- книга читається, але аналіз складності ще триває у фоні;
- підказка завантажується;
- підказка не вдалася;
- непідтримуваний файл (скан без текстового шару, DJVU, пошкоджений файл).

## User flows

**Перше відкриття:** відкрив → бачить демо-книги (public domain) або кнопку
завантаження → обирає → читає.

**Завантаження власної книги:** обрав файл → сервер розбирає → книга відкривається
на першому розділі → читання доступне одразу, аналіз складності доганяє у фоні.

**Читання:** гортає → бачить незрозуміле → виділяє → отримує переклад речення з
підсвіченим фрагментом → закриває підказку → читає далі.

**Повернення:** відкрив додаток → одразу на тому місці, де зупинився.
